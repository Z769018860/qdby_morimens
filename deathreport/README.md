# 死亡游戏调查报告 · 第六十三次回溯筛选

档案终端式的“文档 + 完形填空”推理游戏（同人，《忘却前夜》世界观与素材）。纯静态页面，无需构建。

```bash
python -m http.server 8767           # 打开 http://localhost:8767/deathreport/
cd deathreport && node --test        # 数据与引擎测试（44 项，含三届审计）
python deathreport/tools/ledger.py         # 校验事件账本（时间 / 装备链 / 融灾黑潮 / 杀手存活）
python deathreport/tools/build.py --repo . # 由账本 + 文本重新生成 data/game.json
python deathreport/tools/audit.py          # 三届审计：结构 / 叙事 / 难度 / 吃书
python deathreport/tools/closure.py --strict   # 闭环：只用见证与排除法能否复原 62/62
```

> 命令里的 `python` 在 macOS / Linux 上通常是 `python3`（本仓库的测试脚本两个名字都会试）。

## 玩法（无剧透）
你是弥萨格的守密人，借助溯梦终端复原“第六十三次回溯筛选”里 **62 名唤醒体**的死亡记录，并为每一起死亡填写报告：**死因、凶器、加害人**。

- 在输入栏里键入**记录名**复原记录。记录名由三段组成，怎么拼要自己从线索里推——名册、地图、广播与时间都是线索。
- 记录里的段落可以点击标记；记事本自动保存。
- 记录末尾和索引里的 `[X]` 表示还有几条参考没有复原；虚线表示正文提到了还没读的系统文档。
- 三项全对才会“确认”；填错只会提示“存在错误的报告”。每确认一部分报告，会收到新的消息。
- 提示分三级（先指方向，再指对象，最后给答案），会影响评级。
- 名册、地图、广播与点名都不会白给答案，但它们之间一定对得上。**数一数。**

## 内容规模
62 条死亡记录（含全部 62 名唤醒体）、12 份系统文档、7 条匿名消息、25 格地图与 25 次融灾黑潮封锁、62 件配发装备（取自命轮 / 造物数据）、11 份隐藏档案、18 份补充档案。每条记录有三级「复原提示」与三级「核实提示」。

记录正文**全部手写**（`tools/texts_v2.py` 62/62，往届另有 `tools/ed_62_text*.py`、`ed_61_text*.py`），账本管事实、正文管语气：谁在什么时间什么地点被谁用什么杀死由 `ledger.py` 定死，正文只负责“这个人会怎么讲自己的死”。所以既不会出现“广播人数和死亡顺序对不上”，也不会有两届用同一套句式。

### 内容管线（改剧情时请走这条路）
1. 先改 `ledger.py` 的事件（唯一真相）。`python tools/ledger.py` 会检查：每个人恰好死一次、时间严格递增、杀手当时活着、凶器确实在杀手手里（含夺取与搜尸）、融灾黑潮死亡必须在整点且该区已封锁、其余事件不得发生在已封锁区块。
2. 再改正文。正文**只写令牌，不写事实**：名字、装备名、地名、广播都由账本生成，所以不会出现“广播人数和死亡顺序对不上”这类错误。
3. `python tools/build.py` 重新生成 `data/game.json`，`node --test` 检查：每条答案在正文里有证据（点名 / 装备 / 黑影）、所有记录可由起点 + 消息经引用关系到达、点名人数与名册不一致等。
4. `python tools/audit.py` 跑三届审计（见文末），`python tools/closure.py --strict` 确认 62/62 仍可推。**改完正文务必重跑这两条**——它们抓的是“文字听着对、逻辑不成立”的问题。

世界观、人物与术语取自原作文本提取包（剧情 / 唤醒体档案 / 收藏馆 / 语音）：

- **术语**：银芯（唤醒体的力量与链接媒介，守密人的银钥匙以银芯工艺铸成）、诺斯指数、四界域（混沌 / 血肉 / 深海 / 超维）、守密人、溯梦功能、艾瑞卡（检索权限）。
- **人物**：名册 62 人沿用原作的性别、生日、身高、特性、唤醒台词与简介（名册点击可看）。同名异体（熔毁·朵尔、环行·拉蒙娜、血链·希洛、诞妄·墨菲、蚀灭·萝坦、负誓·奥吉尔）是同一人的另一形态，被同时召入密境，用作“另一个自己”的动机。

- **弥萨格校猫**：原作档案“熟悉的黑猫”（男）；有人骂过“变成黑猫跑掉的臭狗”。

- 原创的部分仅限于：这次“回溯筛选”本身（及其任命书 / 研究背景）、62 起死亡的经过、地图格子的命名。

## 推理系统与闭环验证

- **对应结构**：记录之间的“参考”只有一种——**见证**。较晚死去的人转述较早死者的死：名字、地点、“第 N 个”（死亡顺序）都写在转述里，所以一条见证就足以拼出对方完整的记录名 `NN-XY-SS`。见证只能指向更早的死亡，因此玩家是顺着时间往回读（起始三条取自后半段，最后几条靠匿名消息里的残缺记录名 + 附带的广播录音）。见证计划在 `tools/witness.py`，叙述里的 `{w:N}` 由 `tools/build.py` 渲染。
- **左侧 [N]**：这条记录还能推理出几条尚未复原的新记录；复原一条减一，减到零显示 ✓。索引上方汇总全部可推理数；“结构”页把 62 名唤醒体画成环，线 = 见证关系，点上的 +N 同左侧。
- **闭环验证**：`python3 tools/closure.py` 只允许玩家使用已复原的记录 / 文档 / 消息里写明的信息（名字 → 编号，广播 → 顺序，见证 → 地点与顺序，消息残缺名 → 部分，最后一人按排除法），不动点迭代；必须能复原全部 62 条。`tests/engine.test.mjs` 会运行它，并逐条检查见证是否真的写全了名字 / 地点 / 序数。
- **高亮**：阅读时可开关 人名 / 地点 / 装备 / 广播序数 的自动高亮；点段落循环标记 线索（黄）/ 证词（蓝）/ 矛盾（红）。
- **笔记**：全局记事本（写下记录名可点击复原）、每条记录的独立笔记、线索卡（汇总所有标记段落，点回原文）、对已复原记录的全文检索。
- **推理板**：时间线（含此刻已封锁的区块）、装备流转（每件装备出现在哪些记录里）；报告页会列出该记录出现过的装备与人物，点击即填入，下拉里带 ★。

## 共鸣与补充档案

- **共鸣**：每确认三份报告（3、6、…、60），弹出“共鸣 k/20”：粒子爆发 + 环形涟漪 + 闪屏（`js/fx.js`，尊重 `prefers-reduced-motion`）、一句台词、进度条、本次新到的档案，以及一条**不计入评级**的提示（列出已复原内容里写明下落的人名）。
- **补充档案**（`tools/arcs.py`，18 份 AR-01…AR-18，每确认三份报告送达一份）：不是死亡记录——校史与世界观（弥萨格简史、四界域、融灾黑潮、蹈海者教团、同名异体、银芯析出）、剧情碎片（艾瑞卡的检索日志、校猫目击汇总、管理官通信、回溯研究会纪要、被倒回去的春天）和对诡计的暗示（点名异常、黑影目击汇总、神王·图鲁条目、“致守密人”）。其中带 `{w:N}` 的档案会写全某条记录的名字 / 地点 / 序数，成为新的推理入口，计入左侧 [N] 与结构图；也计入线索卡与检索。
- 闭环验证扩展：`closure.py --strict`（不用广播算术，只用见证、消息残缺名 + 录音、排除法）同样 62/62；测试检查共鸣恰好出现在 3 的倍数且不重复、档案按进度送达、档案里的完整记录名写全。

## 隐藏档案与难度

- **隐藏档案**（`tools/hidden.py`，HX-01…HX-07）：不按进度送达，而按“推理出了什么”打开——确认某一组报告（六组同名异体、校猫窝里的几人、蹈海者三人加图鲁、钟楼里的全部死者、黑潮带走的十一人、夜行者的九名受害者），或连续答对 15 份。索引底部只显示谜面（“？ HX-0n 谜面”），不说条件。
- **难度调校**：报告下拉不再标 ★，“证据清单”（出现过的装备 / 人物）默认折叠；提示三级改为 方向 → 线索所在 → 一个字段（复原：人名与地点，顺序要自己数；核实：只给死因），不再出现完整记录名、凶器或加害人（测试覆盖）。
- **大致难度**（数值来自当前 `game.json` 实测）：起点 3 条，85 条引用 / 62 条记录（平均每条引出 1.4 条），11 条是末梢（不指向任何人），无人指向、只能靠排除法或起始键的 0 条；每条记录平均出现 1.3 件装备、2.5 个人名。62 起死亡里 44 起是他杀，其中 18 起正文会点名，**26 起必须靠证据推**（16 起看装备归属 / 夺取，1 起看行为特征，9 起指向名册外的黑影）。正文 320–542 字（中位 434），死亡跨度 37 小时。预期通关 4–6 小时，纯读不推理会卡在中段（装备链与黑影）。

## 字谜、评分与奖励

- **残片字谜**（`tools/puzzles.py`）：10 份隐藏档案各对应一个两字词。每个字藏在一条“残片”里，如 `〔◇一〕名册第28号的第一项特性，取第四字。`，同符号的残片分散在不同的文本中（记录 / 补充档案 / 系统文档）。规则只有一种：数名册、数地图、数标题、数死者。把词原样键入输入栏，残片所在的文本都已读到时才会有回应。说明见系统文档 `00-FRAGMENT`（从 `00-SYSTEM` 链接过去）。答案以哈希存放，`tests` 用独立的解析器验证每个答案都能从残片拼出。
- **两条路**：同名异体、猫窝、蹈海者、钟楼、夜行者、黑潮这六份既可以字谜解开，也可以靠确认对应的一组报告打开（后者奖励减半）；银钥、倒带、点名、融蚀四份只能字谜；“无错之人”靠连对 15 份。
- **评分**：确认一份 +100；一次答对 +50；字谜 +500 / 成组确认 +250 / 连对 +300；每次提示 −30，每次无效输入 −5。真结局评级 SS ≥ 12500、S ≥ 10500、A ≥ 8500、其余 B；中途收束为 C。
- **奖励**：每份隐藏档案给一枚**勋章**（顶栏与提示页显示 n/11）和一张**提示券**（下一次提示免费、不扣分）。解开时弹出奖励窗并有特效。

## 评价、多结局、往届档案、界面

- **评价**（`rating()`）：档案完成度 55 + 提示节制 20 + 隐藏档案 25，总分 100。SSS ≥ 98（需要全部隐藏档案、几乎不用提示、记录与档案读全）、SS ≥ 90、S ≥ 80、A ≥ 70、B ≥ 55、其余 C。提示券不计入使用次数；每次付费提示 −4%。顶栏实时显示当前评价。
- **多结局**（`tools/endings.py`，真结局按隐藏档案选择，先匹配的优先）：全部 11 份 → 第六十四次；HX-03 + HX-05 + HX-11 → 王摇了头；HX-02 + HX-09 → 猫碗里的名字；HX-08 + HX-10 → 点名完毕；HX-06 → 猫打了个哈欠；其余 → 回溯，启动。中途收束为不完整结局。
- **往届档案**：真结局之后，标题页的“往届档案”打开——**第六十二次·雪夜剧场**（15 名，4×3 的仿造剧院，门口的孩子）和**第六十一次·雾港**（12 名，4×3 的仿造港口，胸口里的东西）。规则、世界、界面相同，故事、名册、地图、凶手与记录完全不同；各有独立存档、独立结局与评价。数据由 `DR_ED=62|61 python3 tools/build.py` 生成 `data/game-62.json` / `game-61.json`（`tools/ed_62.py`、`ed_61.py` 是它们的账本与全部记录；`ledger.py` 在该环境变量下换成对应届次）。测试：`tests/editions.test.mjs`；闭环：`python tools/closure.py --game=data/game-62.json --strict`。
- **界面**：画布装饰层（黑池涟漪、银芯微粒、月光，`js/bg.js`；画布现在是半透明的，让底下的背景插画透上来）、半透明玻璃面板、按届次变化的主题色（六十三次青、六十二次紫、六十一次青绿）、标题页钟楼剪影。

## 手机端、背景与音效

- **手机端**（`@media(max-width:820px)`，不另做一套页面）：
  - 页签从顶栏搬到底栏（52px + `env(safe-area-inset-bottom)`），`body` 的 padding 让位；`.tabs` 横向滚动不换行，地图保底 360px（390 宽的机器刚好放下整张 5×5，更窄的才需要滑）。
  - 所有输入框 `font-size:16px`（iOS 聚焦不再放大），提交键 44px 高，报告下拉 46px，阅读器行距放到 1.85。
  - 核实率从顶栏挪成贴顶 3px 细线；`#toast` 抬到 `calc(70px + safe-area)`，否则新消息提示会压住底栏页签。
  - 结局打字机加了「跳过」，长结局不用干等。
- **背景素材**（`img/bg-*.webp`，每届一张标题页 + 一张阅读页，取自 `assets/gallery-full/` 的横版 CG，缩到 1400px 宽）：`#bglayer` 两层 `<img>` 交替淡入（0.9s），上面压两道遮罩（平铺雾色 + 自上而下渐深），保证正文对比度。切届、进出阅读页都会换图。
- **音效**（`js/audio.js` + `audio/*.wav`）：
  - 7 个音效：敲键、翻纸、确认、错误、盖章、消息、钟声。`play(name,{gain,rate,spread})` 每次随机微调音高与左右位置，避免连点像机器。
  - 环境音是**实时合成**的（不占文件）：每届一组持续低音 + 低通噪声，六十三次是钟楼底下的水声，六十二次是剧院外的风，六十一次是港口的海浪；带 LFO 起伏。
  - 浏览器要求用户先交互才能出声：首次 pointerdown / keydown 时 `unlock()`，之后进游戏自动起环境音，回标题页停掉。素材加载失败时退化成振荡器，不会静音报错。
  - `audio/*.wav` 由 `python tools/make_audio.py` 用纯 stdlib（`wave` + `struct`）合成，改参数重跑即可，不需要 ffmpeg。
- **不落盘的四个音效**（`audio.js` 里的 `synth()`，用振荡器 + 噪声现场合成，所以不多占请求）：
  - `whisper` 黑影的低语：两段带通噪声叠起来，用 4Hz 的 LFO 做出“说话”的音节起伏——只在**第一次**打开名册外那 9 条记录时响。
  - `boom` 黑潮的闷响：78→27Hz 下滑的低频 + 一层低通噪声；第一次打开爆炸致死的记录、以及复原 00-ZONE 时响。
  - `heart` 心跳：两声 66→36Hz 的脉冲；提交最终报告、进入结局时响一次。
  - `lock` 锁扣：两下高通噪声 + 2.3kHz 的金属尾；点地图上的区块时响。
- **特效**（都是 CSS，尊重 `prefers-reduced-motion`）：
  - 正文逐段浮现（`p.fin`，每段错开 22ms，最多 22 段），像记录一行一行被还原；切换高亮时不重播。
  - **黑影记录**：阅读器加 `.shadowrec`——四角暗角（inset shadow）、暗红的分隔线、极轻的抖动（0.5px，7s 一轮）、文字转冷灰。9 条记录一打开就能感觉到“这不是人写的”。
  - 报告确认：印章从 2.4 倍落下（`stampin`），结论行亮一下（`resok`）；手机上同时给一次 24ms 震动，填错是「短-长-短」。
  - 地图：进入时按封锁顺序逐格点亮（每格错开 20ms）；C3 钟楼用一圈呼吸的金边标出“最终收缩”；有已复原记录的区块描边提亮；点区块看这一区死了谁。
  - 结局：黑场用 1.1s 压上来，配心跳。

### 第二轮文本打磨：去模板、加融蚀、自动存档（2026-10-29）

第一轮复查解决的是“对不对”，这一轮解决的是“像不像人写的”。62 条正文全读一遍，问题集中在三处：

**1. 每条记录是同一副骨架。**

起手式几乎都是“地点 + 我 + 配发装备”，中段必有一句“我这一生／我这辈子……”给自己下结论，收尾不是“对不起”就是“光。”。单看一条还行，连着读十条就像同一个人套了 62 个名字。

- 新增 `tools/texts_v3.py`（`T3`，优先于 `T2`），把最容易认出来的 10 条整条重写，并**故意打散结构**：莱克用赌徒的账本口吻（赔率、规矩、记账），阿拉克涅用织工的工作笔记（线、结、别抬头），艾继丝整篇只有听觉（数水滴、铁碰石头），阿格里帕以“重量”为母题，波吕克斯写成口供（回答一个不在场的人），弥利亚姆是守灯人的规矩，珈伦是毒师的专业恐惧（怕的不是死，是“没有味道”），拉蒙娜用引路人的孤独，凯蒂古拉用舞者的身体感，茉夏用洗牌的手感。
- `tools/texts_v2.py` 里就地改掉 30 处重复腔调：9 处“刚才的广播是这样说的”各换成贴着人物与场景的引入；14 处“对不起”压到 5 处（留下有性格的几句）；5 处收尾的“光。”改成各自的死法；8 处“胸口哔哔／发烫”换成不同写法；7 处“我这一生／我这辈子”拆掉一半。

**2. 见证句原来是“一人一句”的死映射。**

`build.py` 的 `CLAUSE` 只有 8 句，用 `(a*7 + b*3) % len` 分配，同一个人作证永远用同一句，84 条推理边压在 8 个句式上。现在改成 25 句的 `SECONDHAND` 池（消息、名单、袖口、闲谈、隔墙、数人头……），索引里混入“这是本条记录的第几处见证”`j`，同一份记录里不会撞句；所有句子只写“听来的／记下来的／有人念过”，不预设目击位置——上一轮那个“我在窗口看见”就是死在这里。

顺带修了三个结构问题：

- **一条记录最多当两次证人**（`witness.CAP`）。原先热门记录会被十来人挑中，于是有的记录里接连冒出三四句“听说 X 是第 N 个”。现在 0/1/2 条见证的分布是 8/24/30；附近都满了就顺延到最近的还有空位的后来者，实在没有才允许超编一份，保证最后几个人也一定有人指向（否则闭包会断）。
- **见证句不再插在正文中间**，统一放在开头（“开场前”的回忆之后、整点广播之后）。插到中间会把对话劈成两半，读者会以为“有人隔着很远在报”是现场台词。
- **不重复通报**：这条记录要是已经把某人的下落写全了（名字＋地点＋第几个），就不再补一句“听说”。注意只认 `{N}` 明文令牌——`{@N}` 只显示名字、不产生参考边，拿它当判据会把往届的推理链剪断（62 届一度只剩 60/62）。
- 另加一条构建期自检：见证句必须同时含 `{B}{P}{N}`，否则 `assert`。有个新模板漏了 `{P}`，玩家能知道“莱克是第 22 个”却不知道死在哪个区块，`closure.py --strict` 直接卡在 `xy?`。

**3. 融蚀只在设定里，正文里没有。**

新增 `tools/melt.py`：8 段“被吃掉的字”插进黑影致死与被融蚀者的记录（14、26、40、49、54、58、50、62），形式各不相同——压痕、四十秒空白、齐口断开、“只剩句号”、读数跳变、纸面浮出的一层黑、几乎读不出来的半句、到最后仪器干脆不输出数字。它们不含任何令牌，也不写人名、序数、封锁时刻，所以不会影响推理与审计。

配合新增文档 `00-MELT`「融蚀观测记录」（从 `00-WORLD` 进入）：63 行读数、名册只有 62 个名字、多出来的那一行没有编号且一直在移动——把主线那个“人数差一”的疑点换了个观测角度讲。文档自己声明了判读要点，其中第二条是本轮的设计说明：**被吃掉的字，前后文仍然通顺**。

界面上，`.meltp` 段落单独一套字色与左边线，缓慢漂移（`prefers-reduced-motion` 下关闭），首次读到带融蚀段的记录会播一个现场合成的 `melt` 低鸣（低频下滑 + 频带塌下来的噪声，不落盘、不加请求）。

**4. 自动存档：关掉页面也能接着玩。**

存档键没变（三届各一份），版本升到 2：

- 每 12 秒自动落一次盘，切后台（`visibilitychange`）、关页面（`pagehide` 与 `beforeunload` 都挂，手机上前者更可靠）再补一次；顶栏的“保存”会闪一下“已保存 ✔”。
- 存的不只是进度，还有**界面位置**：读到哪条、停在哪个页签、报告选的是谁、索引排序。回来点“继续调查”直接落回上次那一页。

### 第五轮：三类“没有第二个人”的死亡，判据写清楚（2026-10-29）

玩家最容易填错的不是凶杀，是**意外死、自杀、封锁致死**——这三种都没有第二个人的动作，却在死因栏里指向完全不同的选项。原来的《死亡报告 填写规定》只说了“三种情形记什么”，没给“凭什么这么判”，于是正文里“我松开了手”和“脚下一滑”看起来同样是摔下去，填错了也说不清哪里错。

**先对账，再写规则。** 三届实测（`playpath.py` 的 `check_classify()` 现在会打印）：

| 届 | 爆炸致死 | 意外死亡 | 自杀（按手法记） |
| --- | --- | --- | --- |
| 63 | 14（封锁整点 13 + 开幕演示 1） | 2 | 坠落 1、中毒 1 |
| 62 | 15（14 + 1） | 3 | 坠落 3、中毒 3 |
| 61 | 15（14 + 1） | 3 | 坠落 4、中毒 3 |

**三条判据**（写进了 `00-REPORT`，玩家随时能从索引里翻）：

1. **爆炸致死**——看两点：时刻是不是整点；此刻这个区块是不是正在被黑潮封锁。两条都中，就是“滞留在封锁区”，记爆炸致死、凶器无、加害人其他。在封锁**之前**死在同一区块的（比如 08:50 死在九点才封的港湾），不是爆炸致死，按实际手法记。开幕演示与自行引爆不受这两条限制。
2. **意外死亡**——致死那一下没有第二个人的动作，也没有“自己要死”的决意。滑倒、踩空、被绊住、抓不住、被塌下来的东西砸中，都算。**从高处落下不一定记坠落致死**：失足、滑落、抓不住的记意外死亡，主动跳落的才记坠落致死。
3. **自杀**——死因栏里没有“自杀”这个选项。按**致死手法**记：跳落记坠落致死，服毒记中毒致死，自行引爆记爆炸致死。加害人记“其他”，**死者本人永远不填在加害人栏**。决意要死却先失手死掉的（想跳却被酒滑倒），仍按实际致死手法记——按“怎么死的”，不按“本来想怎么死”。

**两个顺手堵掉的坑。** 一是“装备在场≠凶器”：`09-A5-25` 詹金戴着潜水头盔滑倒，证据清单里就摆着“◆ 潜水头盔”，点一下正好填错（正确答案是“无”）。证据清单的说明改成“…（点击填入）。装备在场，不等于它就是凶器。”二是“凶器无≠加害人其他”：三届分别有 4 / 2 / 12 条徒手或就地取材的凶杀（石头、断木、尖船桅），凶器记“无”但加害人照常填。

**正文补判据。** 有三条往届的自杀写得像失足，玩家没有依据可判：

- 62 届 `57-B3-02` 阿格里帕：“我往前走了一步，脚下是空的。” → “我往前走了一步——我知道前面没有地板。”
- 61 届 `46-D4-46` 索蕾尔：“栏杆比我想的矮。” → “栏杆比我想的矮——我把手撑上去，翻了过去。”
- 61 届 `52-C2-20` 环行·拉蒙娜：“往窗外走。” → “走到窗边，跨了出去。”

**新检查 `check_classify()`**（常驻，BLOCK 非 0 即失败）：爆炸致死必须是整点且无凶器无加害人；意外死亡必须无凶器无加害人；无加害人的自杀不许填配发装备；**加害人栏不许填成死者本人**；并统计“凶器无却有加害人”的条数——若是 0，说明填写规定里“徒手／就地取材”那条写了但遇不到，会报 WARN。
