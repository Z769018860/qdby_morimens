# 死亡游戏调查报告 · 第六十三次回溯筛选

档案终端式的“文档 + 完形填空”推理游戏（同人，《忘却前夜》世界观与素材）。纯静态页面，无需构建。

```bash
python3 -m http.server 8767       # 打开 http://localhost:8767/deathreport/
node --test deathreport/tests     # 数据与引擎测试（18 项）
python3 deathreport/tools/ledger.py   # 校验事件账本（时间 / 装备链 / 融灾黑潮 / 杀手存活）
python3 deathreport/tools/build.py --repo .   # 由账本 + 文本重新生成 data/game.json
```

## 玩法（无剧透）
你是弥萨格的守密人，借助溯梦终端复原“第六十三次回溯筛选”里 **62 名唤醒体**的死亡记录，并为每一起死亡填写报告：**死因、凶器、加害人**。

- 在输入栏里键入**记录名**复原记录。记录名由三段组成，怎么拼要自己从线索里推——名册、地图、广播与时间都是线索。
- 记录里的段落可以点击标记；记事本自动保存。
- 记录末尾和索引里的 `[X]` 表示还有几条参考没有复原；虚线表示正文提到了还没读的系统文档。
- 三项全对才会“确认”；填错只会提示“存在错误的报告”。每确认一部分报告，会收到新的消息。
- 提示分三级（先指方向，再指对象，最后给答案），会影响评级。
- 名册、地图、广播与点名都不会白给答案，但它们之间一定对得上。**数一数。**

## 内容规模
62 条死亡记录（含全部 62 名唤醒体）、12 份系统文档、7 条匿名消息、25 格地图与 25 次融灾黑潮封锁、62 件配发装备（取自命轮 / 造物数据）。每条记录有三级「复原提示」与三级「核实提示」，全部由账本模板生成。

## 结构
```
index.html  css/dr.css  js/ui.js     界面：标题 / 索引 / 阅读器 / 名册 / 地图 / 报告 / 记事本 / 提示 / 结局
js/engine.js                          纯逻辑：记录名解析、参考计数、报告判定、消息解锁、提示阶梯、结局
data/game.json                        生成物（不要手改）
tools/ledger.py                       事实账本：62 起死亡的时间、地点、死因、凶器、加害人、装备流转 + 全部校验
tools/texts.py texts_extra.py         记录正文（带 {名字} {it:装备} {loc:区块} {bc:广播} 令牌）
tools/docs.py                         系统文档与匿名消息
tools/build.py                        账本 + 文本 → game.json（解析令牌、生成广播、参考图、提示、解答）
tests/engine.test.mjs                 完整性、可达性、证据存在性、装备链、反转的约束、完整通关
```

### 内容管线（改剧情时请走这条路）
1. 先改 `ledger.py` 的事件（唯一真相）。`python3 tools/ledger.py` 会检查：每个人恰好死一次、时间严格递增、杀手当时活着、凶器确实在杀手手里（含夺取与搜尸）、融灾黑潮死亡必须在整点且该区已封锁、其余事件不得发生在已封锁区块。
2. 再改正文。正文**只写令牌，不写事实**：名字、装备名、地名、广播都由账本生成，所以不会出现“广播人数和死亡顺序对不上”这类错误。
3. `python3 tools/build.py` 重新生成 `data/game.json`，`node --test` 检查：每条答案在正文里有证据（点名 / 装备 / 黑影）、所有记录可由起点 + 消息经引用关系到达、点名人数与名册不一致等。

## 创作者说明（含剧透）
**反转**：名册上只有 62 人，其中 50 号“图鲁”的档案被融蚀（名字糊成 ▇▇，配发装备也读不出来）——它诱使玩家以为“黑影 = 那个融蚀的唤醒体”。其实图鲁在第一天上午就死了（记录 10），而黑影在夜间才开始行动；黑影用的全是已封锁区块里死者留下的装备，说明它**没有银芯**、能进入融灾黑潮区域。点名与广播的人数始终比名册多一人（63 − 死亡 = 现存），所以存在名册之外的第 63 个参加者：作为黑影存在的**神王·图鲁**，他是最后的胜者。加害人栏在收到 MSG06（确认 50 份报告后）才会追加“名册外的个体（黑影）”。
**幕后**：弥萨格校猫。它在开幕时压着遥控器（记录 01），在猫窝附近反复出现（记录 12 / 37 / 44 / 56），用 62 枚银芯里保存的“最后五分钟”做回溯的资源，目的是重新唤醒神王。最后一条消息告诉你：你每复原一条记录，它的锁就松一格。
**结局**：确认全部 62 份报告 → 真结局（MSG07 与机密文档 00-DECREE / 00-SEALED）；中途「提交最终报告」（≥31 份）→ 不完整结局，可继续调查。
**免责声明**：所有剧情为同人虚构，使用真实唤醒体的名字与官方图标，但不代表官方设定；玩法灵感来自“填写死亡报告”类推理游戏，故事、文本、名册与谜题均为原创。

## 与原作设定的对应

世界观、人物与术语取自原作文本提取包（剧情 / 唤醒体档案 / 收藏馆 / 语音）：

- **世界**：弥萨格大学（洪积90年由华德·菲利普斯、刻拉尔克什、塔薇创立）与其地下的黑池；融蚀（自洪积15年起近三百年）、融灾黑潮、灾厄；《密斯底亚协定》与审查会；迷雾屏障；人工密境（世界复本）。
- **术语**：银芯（唤醒体的力量与链接媒介，守密人的银钥匙以银芯工艺铸成）、诺斯指数、四界域（混沌 / 血肉 / 深海 / 超维）、守密人、溯梦功能、艾瑞卡（检索权限）。
- **人物**：名册 62 人沿用原作的性别、生日、身高、特性、唤醒台词与简介（名册点击可看）。同名异体（熔毁·朵尔、环行·拉蒙娜、血链·希洛、诞妄·墨菲、蚀灭·萝坦、负誓·奥吉尔）是同一人的另一形态，被同时召入密境，用作“另一个自己”的动机。
- **神王·图鲁**：原作里的图鲁是神王的“切片”——孩子面容、怕水、贪睡、被困在漫长的梦里；黑影则是完整的神王：满是尖刺的王冠、半透明的触腕、怕水、不在任何档案里，遗体上没有银芯析出。
- **弥萨格校猫**：原作档案“熟悉的黑猫”（男）；有人骂过“变成黑猫跑掉的臭狗”。
- **62 条记录**（`tools/texts_v2.py`）：按各人原作的身份、能力与口吻重写（如图鲁自称“余”、旺达看不见、奥吉尔坚信自己五尺高、希洛与莉莉互相寻找、同名异体互相照面）。事实骨架仍由 `ledger.py` 决定；`tools/check_v2.py` 校验每条重写没有丢失引用 / 装备 / 地名 / 广播标记，也没有提前点出需靠证据推断的加害人。
- 原创的部分仅限于：这次“回溯筛选”本身（及其任命书 / 研究背景）、62 起死亡的经过、地图格子的命名。

## 推理系统与闭环验证

- **对应结构**：记录之间的“参考”只有一种——**见证**。较晚死去的人转述较早死者的死：名字、地点、“第 N 个”（死亡顺序）都写在转述里，所以一条见证就足以拼出对方完整的记录名 `NN-XY-SS`。见证只能指向更早的死亡，因此玩家是顺着时间往回读（起始三条取自后半段，最后几条靠匿名消息里的残缺记录名 + 附带的广播录音）。见证计划在 `tools/witness.py`，叙述里的 `{w:N}` 由 `tools/build.py` 渲染。
- **左侧 [N]**：这条记录还能推理出几条尚未复原的新记录；复原一条减一，减到零显示 ✓。索引上方汇总全部可推理数；“结构”页把 62 名唤醒体画成环，线 = 见证关系，点上的 +N 同左侧。
- **闭环验证**：`python3 tools/closure.py` 只允许玩家使用已复原的记录 / 文档 / 消息里写明的信息（名字 → 编号，广播 → 顺序，见证 → 地点与顺序，消息残缺名 → 部分，最后一人按排除法），不动点迭代；必须能复原全部 62 条。`tests/engine.test.mjs` 会运行它，并逐条检查见证是否真的写全了名字 / 地点 / 序数。
- **高亮**：阅读时可开关 人名 / 地点 / 装备 / 广播序数 的自动高亮；点段落循环标记 线索（黄）/ 证词（蓝）/ 矛盾（红）。
- **笔记**：全局记事本（写下记录名可点击复原）、每条记录的独立笔记、线索卡（汇总所有标记段落，点回原文）、对已复原记录的全文检索。
- **推理板**：时间线（含此刻已封锁的区块）、装备流转（每件装备出现在哪些记录里）；报告页会列出该记录出现过的装备与人物，点击即填入，下拉里带 ★。

## 共鸣与补充档案

- **共鸣**：每确认三份报告（3、6、…、60），弹出“共鸣 k/20”：粒子爆发 + 环形涟漪 + 闪屏（`js/fx.js`，尊重 `prefers-reduced-motion`）、一句台词、进度条、本次新到的档案，以及一条**不计入评级**的提示（列出已复原内容里写明下落的人名）。
- **补充档案**（`tools/arcs.py`，18 份 AR-01…AR-18，每确认三份报告送达一份）：不是死亡记录——校史与世界观（弥萨格简史、四界域、融灾黑潮、蹈海者教团、同名异体、银芯析出）、剧情碎片（艾瑞卡的检索日志、校猫目击汇总、管理官通信、回溯研究会纪要、被倒回去的春天）和对诡计的暗示（点名异常、黑影目击汇总、神王·图鲁条目、“致守密人”）。其中带 `{w:N}` 的档案会写全某条记录的名字 / 地点 / 序数，成为新的推理入口，计入左侧 [N] 与结构图；也计入线索卡与检索。
- 闭环验证扩展：`closure.py --strict`（不用广播算术，只用见证、消息残缺名 + 录音、排除法）同样 62/62；测试检查共鸣恰好出现在 3 的倍数且不重复、档案按进度送达、档案里的完整记录名写全。
