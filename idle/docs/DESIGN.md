# 设计文档（M0–M15）

## 1. 目标
网页端可玩的挂机自动战斗原型，验证「自动战斗好不好看、养成循环顺不顺」。核心逻辑与 UI 分离，便于后续移植微信小程序（M5）。

## 2. 数据
来源：`qdby_chinese/data/morimens/skeydb/public-v3`（角色/命轮/密契/造物，含 Lv1 属性与成长系数）与 `game/tier-pool.json`（中文名与图片路径）。
- 角色属性：`hp = CON×10`、`atk = ATK×2.2`、`def = DEF×1.6`，均随等级按 `statScaling` 线性成长；暴击等副属性按 `substatScaling`/10 成长；每叠位 +1.5%（M9 之前是每星 +8%，5 星封顶）。
- 技能：源数据只有文字模板，因此本作使用自己的「效果原型」：`dmg / heal / shield / buff / debuff / dot / gauge / lifesteal`，按（类型 × 领域）生成 7 槽技能组，再对 12 名角色做招牌覆盖（`src/core/skills.js`）。技能说明由效果自动生成，保证文字与数值一致。
- 怪物：`tier-pool.json` 的 295 个怪物（普通 132 / 精英 53 / Boss 110），按关卡种子确定性抽取。

## 3. 战斗
回合制，同一回合内我方依次行动、再到敌方。事件流（`events`）在模拟时一次生成，UI 按固定节奏回放（**没有倍速，也没有「极速跳过」，见 §12**）；离线结算与手动挂机的即时判定直接用结果。
- 能量：共鸣能量（攻击+14、技能+20、受击+9）满 100 放共鸣；共鸣释放 +34 钥焰，钥焰满 100 放超共鸣；回合 1 先放唤醒。
- 选牌 AI：唤醒 > 超共鸣 > 共鸣 > 低血架势 > 合唱按需治疗 > 技能二 > 技能一 > 攻击（技能有冷却 3/2 回合）。
- 伤害：`atk × 倍率 × (1+增伤) × 暴击 × 防御减免(def/(def+150))`，±5% 浮动。
- 敌方：普通/精英/Boss 各有循环招式；第 12 回合起狂暴；词缀（狂暴/坚壳/蚀咬/迅捷）。30 回合未分胜负算失败。
- 策略预设只调整「低血架势阈值」与「集火目标」。

## 4. 养成与经济
| 系统 | 规则 |
|---|---|
| 升级 | 金币，`40×lv^1.45`；上限 `60 + 叠位`（硬顶 159）；每 20 级一次「突破」，金币 `4×lvUpCost(lv)` + 银芯 `20+lv`，不突破就升不动 |
| 叠位 | 重复抽取 +1，上限 99。每叠位全属性 +1.5% 且等级上限 +1；每 10 叠位 +3% 增伤；每 40 叠位技能等级 +1（最多 +2）；已满时重复折算 💠30 |
| 技能等级 | 每 15 级 +1 档，再加叠位加成，最高 4（显示 Lv.1–5） |
| 命轮 | 每人 1 个；主属性映射到本作属性；同领域 ×1.25 |
| 密契 | 每人 1 个；全队同款 2/4 件触发套装（8 种主题，按编号分配） |
| 造物 | 全队 6 栏被动（10 种主题）；开局 3 栏，最高通关 20/45/75 各开一栏，只有已解锁栏里的生效；同主题 2/4/6 件触发羁绊 |
| 钥令 | 全队 3 格（通关 1/12/35 解锁），原作 63 件（R 42 / SR 15 / SSR 6，图标为原作 `KeyToken_*.webp`）；淬炼 5 级、每级 +15% 效果；同一件不能占两个位置 |
| 装备强化 | 金币，上限 10 级，每级 +10% |
| 召唤 | 精良 60% / 史诗 37% / 创生 3%，38 抽起提升、50 抽必出创生，十连保底史诗 |
| 掉落 | 每场胜利：金币 + 10% 装备（Boss ×3）+ 召唤券（基础 1/40）+ 银芯（基础 1/90），**两者随关卡缓慢提升**（每关 +1.8% / +2.6%，见 §14）；零头累进 `state.drip`；首通送召唤券（Boss 3 张 + 20 银芯 + 装备 + 1 枚钥令） |
| 离线 | 每 25 秒一场（144 场/小时），最多 8 小时，按当前关卡胜率估算，与收益面板同一公式 |

推进规则：每场都有**回合上限**（普通关 18、Boss 关 22，见 §14），打满还没清场就是超时判负，不算通关也不推进。**自动**模式下胜利且「从容」（存活 ≥3 人、回合不超限）才自动前进，在前线失败会退回上一关挂机；**手动挂机**（关掉「自动挂机」）时照常连打，但**不自动推进**——只更新最高通关，关卡由玩家用右上角 ◀ ▶ 自己选，赢了留在本关继续刷，输了也不会被踢回去（撤退只在自动模式生效）。手动因此是「换一档挂机收益」的工具，而不是「偷跑一关」的捷径。

## 5. 数值验证
`npm run sim` 用贪心机器人玩 4000 场（一场按 25 秒算，400 场 ≈ 2.8 小时；机器人现在也走「一键配队」，命轮/密契/造物/钥令都按同一套规则上）：约 400 场到第 36 关，800 场到第 40 关、1200 场到第 49 关、2000 场到第 59 关，之后进入长草（队伍 70 级、无限塔 49 层、竞技场 18 名、融灾 33 关）。M11 加了回合上限之后单场更短、但前线更难过——曲线总量和 M10 基本持平。机器人不做银芯叠位、不手动换关，真人曲线会更快。

## 6. M3：真实技能、状态与挑战
**技能**：游戏的 7 个技能槽与原作卡牌槽（打击 / 防御 / 技能 1 / 技能 2 / 灵知觉醒 / 狂气爆发 / 超限爆发）一一对应，因此每个槽直接采用原作的中文名称与说明。数值仍由本作的「效果原型」决定（`typeKit` 基准 + 招牌覆盖），再按原作文本里的关键词附加至多 2 个「骑手效果」：中毒/侵蚀 → 中毒层数；易伤、虚弱、力量降低 → 对应减益；反击、屏障、护垒 → 自身状态；力量 → 攻击增益；文本含「全体敌人」→ 单体伤害改为群体（×0.7）。这样 62 名角色各有辨识度，又不破坏基准平衡。
**状态**（`battle.js`）：中毒（回合开始结算纯粹伤害，层数每回合衰减 20%，上限 40）、出血（原有 DoT）、易伤（受伤 +x%）、虚弱（造成伤害 ×0.75）、反击（被攻击时反伤）、力量（攻击增益）、屏障（挡下 N 次攻击）、护垒（减伤）、脆弱（护盾 ×0.75）、封印（无法放共鸣/超共鸣）。事件流新增 `st / status / counter`，UI 用原作关键词图标显示。
**敌人**：每个怪物的招式由其原作技能行解析（伤害 / 群攻 / 中毒 / 虚弱 / 易伤 / 护盾 / 回复…），伤害预算沿用原先每阶级的模板，保证至少含攻击招式。
**无限塔**：每日 3 次，每次从第 1 层打起，存活者生命继承并回复 30%，全灭为止；`towerStage = 10 + 0.95×层`，每 5 层 2 张召唤券，每 10 层掉装备，仅首次到达的层数有奖励。
**融灾试炼**：取自第 71/72 期客户端节点导出的各区域首领（含多首领区域），C/B/A/S/SS/SSS 对应关卡强度 26/34/42/50/60/72，依次解锁，首通奖励召唤券 1/2/3/5/8/12 + 装备，重复挑战给金币。
**成就**：25 项（推图、胜场、收集、叠位、装备、塔、试炼），奖励召唤券/金币。**新手引导**四步。**伤害统计**：战斗与挑战结算均显示每名队员的伤害 / 治疗。
**数值验证**：`npm run sim`（含每 400 场一次的塔与试炼）——约 400 场到第 29 关，约 2000 场到第 39 关形成墙；无限塔随进度到 30+ 层；试炼 C 档早期可过，B 档中期，A 以上需要明显更强的养成。

## 7. M4：怪物设计同步、数值细化、音效
**怪物**：`tools/build_monsters.py` 读取客户端怪物表（`maps/monsters.json`）：阶级 `c`、体型 `b`、`hp/atk/df` 系数、开场 `op` 与循环 `cy` 的技能 ID 序列，以及技能表（文本、意图、公式、目标）。公式按位置给出参数：`BattleAtkForce*0.8,1,1` → 伤害 ×0.8 攻击、1 次、1 回合；`BattleDefForce*2.5` → 护盾 ×2.5 防御。名称取 `main` 的 `official-terms.json`（官方译名优先），特征取 `dictionary.json`。去掉训练木桩，保留 537 个、964 个技能；图标取客户端意图图（15 种）。
**换算**（`monsters.js`）：伤害 = 系数 × 攻击（单次，单个招式总倍率封顶 3.4，群攻 ×0.65）、护盾 = 0.5 × 防御系数、力量 = 攻击系数 ×100% 的增伤（6–40%，3 回合）、中毒/脆弱/虚弱的层数与回合取公式里的真实数值（上限 8 层 / 4 回合），出血、反击、屏障、护垒等沿用关键词效果；召唤、弃牌、塞牌等本作没有的机制只保留文本。
**敌人属性**：阶级基础值（普通 1 / 精英 2.4 / 首领 5.5 倍血量）× 钳制后的真实系数（血 0.5–1.8、攻 0.75–1.25、防 0.6–1.8）。出招 = 开场序列走一遍，再循环 `cy`；战斗事件流新增 `intent`（下一招的意图图标与名称），UI 在敌人头顶显示。
**数值**：唤醒体技能从原文提取数值区间（伤害%攻击、护盾%防御、狂气），对同槽位同等级的中位数取比值（钳制 0.55–1.8）缩放对应效果；原型里没有伤害 / 护盾但原文有的（如徐的技能一）按槽位预算补一个效果。技能等级同时受等级与叠位影响：`min(4, min(3, ⌊(lv−1)/15⌋) + min(2, ⌊叠位/40⌋))`（M9 起；M4 原式为 `⌊(lv−1)/59×3.4 + ★×0.25⌋`，它随等级上限变化会倒挂，已废），整体乘 `0.98 + 0.03×等级`，所以升级、叠位会让技能真正变强，同时不动平衡中位线。敌人攻击基数 34→30 以抵消真实多段招式带来的伤害上升。
**图鉴**：`state.codex[怪物id] = {seen, kills}`（推图与试炼记录），新增成就「初识异形 / 融蚀图鉴 / 首领猎手」。
**音效**（`ui/audio.js`）：WebAudio 振荡器 + 噪声合成，23 种音效；命中按攻击者界域换音色（混沌锯齿、血肉浊音、深海带通噪声、超维方波）；同名音效有节流，防止一回合多段攻击把音效糊成一片（M9 去掉倍速后不再需要按速度适配）；背景是缓慢失谐的低音 + 稀疏五声音阶，Boss 战加入低频脉冲。音量与静音存 `localStorage`（不进游戏存档）。
**验证**：`npm test`（27 项）；`npm run sim` 曲线与 M3 相当（约 300 场到 29 关，约 3000 场到 40 关形成墙）。

## 8. M5：周 Boss、属性塔、竞技场
**周 Boss**（`weekly.js`）：`weekId` 为 UTC 的 ISO 周；Boss = 首领池（循环 ≥2 招，按 id 排序）里 `hash(周)` 取模，保证同一周所有人遇到同一个。强度按第 48 关，血量设为 1e12（只算伤害），12 回合封顶；每日 3 次（按 UTC 日期重置），周累计伤害 8 档里程碑（1万→70万）各领一次，第 4/6/8 档附装备。里程碑按机器人曲线标定：单次伤害约 3k（第 600 场）→ 18k（第 3000 场）。
**属性塔**（`rtower.js`）：`rtStage = 8 + 1.05×层`，第 5 层精英、第 10 层首领；队伍 = 该界域已拥有的战力最高 4 人（同界域加成照常生效）；敌人池按怪物特征 `Caro / Aequor / Ultra` 过滤（混沌没有对应特征，用全部）。每层一场，失败不扣次数，首通奖励金币 + 每 3 层 1 券 + 每 10 层 3 券与装备。
**竞技场**（`arena.js`、`friend.js`）：
- 天梯：名次 1–100，未上榜 = 101；对手 = 比自己高的 5 个名次，全部是人机。`botEntry(rank)` 由名次做种子确定性生成：等级 2→60、叠位 0→4、装备折算 ×1→×1.55，名次越靠前越偏向同界域 3 人组（触发界域加成）。
- 好友对战：不设服务器。`encodeCode` 把当前队伍（slug / 等级 / 叠位 / 最终属性）和昵称序列化为 `MMX1-<base64url(JSON)>-<4位校验>`，约 350 字符；对方粘贴后 `decodeCode` 校验并还原，用同一套战斗引擎模拟。技能由等级重建、数值读取时做上限钳制（`lv≤159`、叠位 `≤99`）；校验只防复制错误，不防作弊——所以友谊赛没有奖励，只记录每位好友的胜负（最多 20 条）。
- 战斗引擎改动：有 `kit` 的单位无论哪一方都按技能组 AI 行动（原先只有我方），因此对手队伍用的是和我方完全相同的技能系统。
**奖励**：胜利金币，最高名次每提升 2 名 1 张券，每日排名奖励（1 名 20 券 … 100 名 3 券）。新增 7 个成就。
**验证**：`npm test`（30 项）；`npm run sim`（每 400 场试周 Boss / 四塔 / 竞技场）：约 3000 场后周 Boss 单次约 18k、属性塔 16–36 层、竞技场到第 37 名。对战码有编码解码、篡改与截断校验、无奖励的测试。

## 9. M6：银芯经济、装备精炼、签到、成就扩充
**银芯**（`state.cores`，初始 300）——次级货币，定位是「慢速、可控的加速器」，不取代召唤券：
- 收入：首通普通关 4 / Boss 关 20、首次击败某个首领 5、无限塔每 5 层 15、属性塔每 5 层 12（10 层 +20）、试炼首通 `15×券数`、周 Boss 里程碑 `10×券数`、竞技场最高名次每提升 1 名 2（上限 60）与每日排名奖励 `5×券数`、签到（日常 10，7 的倍数 40，累计宝箱 40–300）、成就（阶梯 8→100）、离线 `胜场/90`、分解 SR 2 / SSR 6 + 精炼返还一半、满星重复 30。
- 支出：银芯召唤 200/抽、十连 1900（共用保底）；精选祈愿 80（SR 以上装备）；装备精炼 40/80/140/220/320；商店（召唤券 120 ×10/日、金币 5000 = 40 ×5/日、装备 60 ×5/日、周 Boss / 无限塔 / 竞技场额外次数 50/40/30 各 ×3/日）；补签 40。
**精炼**：`rf` 0–5，`scaleBonus(bonus, 1 + 0.08×rf)` 作用于该装备的全部加成（命轮、密契、造物同一规则）。
**签到**（`signin.js`）：UTC 月历，`state.signin = {month, claimed[], cum[]}`，月变更自动重置；日常奖励 3 券 + 金币 + 10 银芯，7 的倍数日 8 券 + 40 银芯 + 装备；累计 5/10/15/20/25/28 天宝箱；补签 40 银芯。旧的「每日奖励」并入签到。
**成就**：`tiers()` 工厂生成阶梯成就（id = 基名 + 目标值，旧存档 id 保持不变），共 109 个、11 类；奖励随阶梯上升；`claimAllAchievements` 循环领取（「总览」类成就依赖已领数量，会连锁解锁）。
**验证**：测试 37 项；机器人曲线里银芯召唤使 3000 场时图鉴收集更快（62 名唤醒体），战力曲线基本不变。

## 10. M7：注册福利与战斗特效
**注册福利**（`welcome.js`）：门户项目的登录态保存在 `localStorage['zjtt:authToken' / 'zjtt:authUser']`，游戏与门户同源，因此可以只读这两项判断「是否已登录」并取账号名（去掉 `@zjtt.local`、NFKC 小写作为 key），不发网络请求，也不改动门户代码。福利一次性：银芯 1000 + 召唤券 10 + 金币 5000 + 装备；已领账号 key 记录在独立的 `localStorage['morimens-idle-welcome']` 列表里，所以重置存档、导入别的存档都不能再领（但清空浏览器数据可以——这是君子协定，要硬约束需要服务端）。7 日新手福利按 UTC 天数从领取当天算起，第 N 天可领，错过的可在 7 天补领窗口内补齐，之后过期；总计银芯 1200。游客在签到页看到「去首页登录 / 注册」入口，已登录且未领取时启动会有提示。
**战斗特效**（`fx.js`）：绝对定位在战场上的 `<canvas>`（DPR ≤2）+ 一个闪光层；粒子类型：火花、冲击环、斩击线、攻击轨迹（渐变）、箭头、气泡、彩带；`lighter` 混合叠加发光；粒子上限 420，「简化」模式下数量 ×0.4（M9 之前随倍速 `1/√speed` 缩减、极速模式不触发，倍速下线后这层适配一并去掉）。粒子清空后停止 `requestAnimationFrame`。与音效一一对应挂在 `BattleView.apply` 的事件上（act / dmg / dot / heal / shield / buff / status / die / end）。颜色取攻击者界域（混沌红 / 血肉橙 / 深海蓝 / 超维紫）。
**验证**：测试 39 项（含福利领取一次、账号级去重、7 日窗口）；Chromium 中取帧确认特效层有像素、无报错。

## 11. M8：详细结算

## 15. M12：挂机收益的召唤券 / 银芯随关卡缓慢提升

M11 只补了「爬塔每层给一点」，玩家真正花时间的地方是**推图挂机**，那里券和银芯原本是死值：`TICKET_PER_WIN = 1/40`、`CORE_PER_WIN = 1/90`，不管挂第 3 关还是第 60 关，每场给的一样多——金币随 `stageGold` 指数涨，券/银芯却原地踏步，越往后挂机越「只出钱不出资源」。

现在把这两个掉率改成关卡函数（`game.js`）：

```js
export const ticketBoost = (stage) => 1 + Math.max(0, stage) * 0.018;   // 券：每深一关 +1.8%
export const coreBoost   = (stage) => 1 + Math.max(0, stage) * 0.026;   // 银芯：每深一关 +2.6%
export const ticketPerWin = (stage) => TICKET_PER_WIN * ticketBoost(stage);
export const corePerWin   = (stage) => CORE_PER_WIN * coreBoost(stage);
```

线性的，不用 `Math.pow`——指数在这个量级上 300 关就会翻几十倍，而主线关数本身没有硬上限。实测面板（满胜率）：

| 关卡 | 券/小时 | 银芯/小时 | 平均几场 1 张券 | 平均几场 1 枚银芯 |
| --- | --- | --- | --- | --- |
| 1 | 3.7 | 1.6 | 39 | 88 |
| 30 | 5.5 | 2.8 | 26 | 51 |
| 60 | 7.5 | 4.1 | 19 | 35 |
| 100 | 10.1 | 5.8 | 14 | 25 |
| 200 | 16.6 | 9.9 | 9 | 15 |

银芯涨得比券快（+2.6% vs +1.8%）：淬炼、叠位、商店都吃银芯，它才是真正卡人的资源；券主要受限于召唤保底与每日收益，不宜放太快。

**口径统一**：`farmRate` 用新函数算 `ticketsPerHour / coresPerHour`，并额外返回 `ticketBoost / coreBoost / winsPerTicket / winsPerCore` 供面板展示；`applyResult` 的在线零头 `drip.tickets += ticketPerWin(res.stage)`；`offlineReport` 按 `wins × 同一个函数` 取整，并把小数余量作为 `ticketFrac / coreFrac` 交给 `claimOffline` 写回 `state.drip`——之前离线的小数部分是直接丢掉的，现在和在线完全同一套账。

## 16. M13：编队、程序化 BGM 与音效重做、抽卡记录与欧非

### 16.1 编队（`core/squad.js`）
挑战模式原本一律读 `state.team`，玩家想「推图一套、爬塔一套、周本一套」就只能反复改队伍，而改队伍会同时影响正在挂的图。现在：

- `state.squads = { a|b|c: { team: [slug×4] } }`，**只存 4 个人**。命轮、密契绑在唤醒体身上会跟着走；造物与钥令是全队被动、本来就共用——存装备只会带来「两份配置打架」的问题。
- `state.squadPick = { tower|rtower|weekly|trial|arena: 'cur'|'a'|'b'|'c' }`，每个挑战入口各记一份。
- `teamSlugsFor(state, mode)` 是唯一出口：`'cur'` 用当前队伍；编队为空、成员已被删、或全都不合法时**退回当前队伍**，永远不会拿空阵去送。
- 挑战侧改签名而不是偷换 `state.team`：`simulateTower(state, data, { slugs })`、`doTower(state, data, { slugs })`、`doWeekly(state, data, slugs)`、`doTrial(..., slugs)`、`doRTower(state, data, realm, slugs)`、`fightArena(state, data, entry, slugs)`。`doTower` 的第三参兼容老的 `today` 字符串写法，测试不用改。
- 属性塔保留界域限制：编队里的其他界域成员被剔掉，一个都不剩才回退成「自动挑本界域最强的 4 个」（`rtTeam`）。
- `normalizeSquads/normalizePick` 在 `migrate` 里跑一遍：剔除已不存在的 slug、去重、截到 4 人、丢弃非法入口——老存档直接升级。

### 16.2 背景音乐与音效（`ui/audio.js`）
原来只有一条「锯齿波长音 + 随机五声音」的氛围垫，音量极低、没有节奏，实际听着像没开音乐。M13 把它换成真正的 step sequencer：

- `TRACKS` 里六首：城镇 64bpm / 推图 88 / 战斗 108 / 首领 138 / 召唤 74 / 挑战 96，各带调式（minor / dorian / penta）、和弦级数循环与六个声部（pad / bass / arp / lead / perc / hat）的音量系数。
- 三和弦由「级数 + 调式音阶」叠三度生成，所以任何和弦都在调内；琶音在三个和弦音之间走并左右 ±0.25 声像摆开；主旋律只落和弦音，随机只决定「弹哪个、什么时候弹」。
- 排程不用 `setTimeout` 直接发声：每 40ms 跑一次 `tick()`，把未来 0.3 秒内的 16 分音符全部排进 AudioContext 时钟（`pad/bass/arp/lead/kick/snare/hat` 各自 `start(t)`），JS 定时器抖动不会影响节奏。
- `setMood(key)` 跟页面走；`crossfade` 先 0.35s 淡出、换曲再 0.9s 淡入，旧音符自然衰减。`cfg.autoMood=false`（用户在设置页锁了曲目）时 `setMood` 只记录不切曲。Boss 战由 `BattleView` 直接切「威压」。
- 音效补齐 `coin / buy / deny / unlock / stamp / reveal1-3`，命中类加 6% 微失谐；抽卡按最高稀有度选 `reveal3 / reveal2 / reveal1`。
- 顶栏加喇叭按钮（`#sndq`），一次点击切换静音，设置页的音量 / 曲目与它双向同步。

### 16.3 抽卡记录与欧非（`core/gacha.js`）
`recordPull` 在 `summon` / `summonCores` 里逐抽调用，写 `state.gacha.log`（**只留最近 300 条**）与聚合计数 `agg{pulls,Genesis,SSR,SR}`。明细会裁剪，指数用聚合算：

```js
货值   = Genesis×100 + SSR×18 + SR×1
期望   = pulls × (0.03×100 + 0.37×18 + 0.6×1) = pulls × 10.26
幸运指数 = round(货值 / 期望 × 100)        // 100 = 平均水平
```

权重取 100 / 18 / 1 而不是直接用「抽数」，是因为一个创生和一个精良对账号的意义差了两个数量级，用抽数算会让「出了创生但其余全非」显示成普通人。五档评价用 160 / 120 / 85 / 55 分段：抽得越多越难偏离 100，所以指数本身对抽得多的人不苛刻。另外记录 `best10`（一次十连里史诗以上的个数），面板上给「最好十连」一个位置。

### 17.1 属性塔按界域拆成四个入口

### 17.2 编队的三层入口
- **队伍页「挑战编队」**（`squadAssignPanel`）：8 行一次列全，每行显示当前选中的编队名、人数、战力、4 个头像和四个 chip。点 chip 就是 `setSquadPick`，和挑战页共用同一份 `state.squadPick`，不存在两套配置。

### 17.4 观战回放
挑战模式原本点一下就 `openModal` 出结算，看不到任何过程。现在 `simulate` 额外返回 `prep`（双方 `uid / name / img / type / realm / hp / boss / reward / openAli / openKey`），`roundLimit` 与 `events` 本来就有，于是挑战结果天然可以回放。

- `ui/replay.js` 的 `Replay` 类：复用战斗页的 `.field / .unit / .bar / .float` 样式与音效，自己维护 `units` 表，按事件类型给 PACE（round 340ms、act 230ms、dmg 70ms…）逐条 `setTimeout` 推进；只读不写状态——**结算在打开播放器之前就已经跑完了**，所以中途跳过 / 关掉都不会影响结果。

- `watchOrSkip(spec, done)` 读 `watchMode`（localStorage，默认 `watch`）：`skip` 或没有事件流时直接 `done()`，行为与 M13 完全一致。

- 设置页「挑战过程」只有两个选项，不做第三种「每次询问」——询问框在连打场景里只会变成无脑连点。

### 17.5 唤醒体排序
`core/roster.js` 的 `sortRoster(rows, key, dir)` 是纯函数：`rows = { a, r, idx, power }`，`key ∈ rarity / power / lv / star / order / realm`，`dir = ±1`。规则：
- **未获得的永远排在拥有之后**，不随 `dir` 翻转；
- 同分时按 `idx`（获取顺序）收尾，列表不会每次重绘都换位置；
- 非法键退回稀有度，UI 传错也不炸。

`idx` 取自 `Object.keys(state.roster)` 的下标——JSON 保留插入顺序，召唤新角色是往末尾加，所以它就是获取顺序，不需要额外存字段。

## 18. M15：融灾禁区（五队齐上的 100 层爬塔，每两周一期）

### 18.1 为什么是「五队」而不是「一队爬五遍」
挑战组已有的无限塔是「一支队伍、生命继承、一次爬到全灭」，考的是单队续航。融灾禁区要考的是**池子深度**：你要凑出五套能独立作战的 4 人队。所以每层固定 5 场战斗，第 i 场由第 i 队打，敌人组各自独立（同层不同种子），互不继承血量。

### 18.2 判定：5 场胜 4 场即通过
一开始写成「五场全胜」时，实测下来曲线是断崖：满配置队伍在 stage 26 能 5 场全胜，stage 28 突然 0/5——因为 18 回合上限下，**怪物组合**（坚壳 affix 的厚皮 + 会叠护盾的精英）比队伍强度更能决定胜负。5 场全胜等于把这个运气放大 5 倍，一层通过率只剩三成。改成 `RIFT_PASS = 4` 后容错回来了，而且「漏掉的那队」在结算里单独标红，玩家能看出是哪一队顶不住。

### 18.3 数值
```js
riftStage(f) = round(10 + f * 0.55)   // 第 1 层≈11 关，第 100 层≈65 关
五队里第 5 队打精英/Boss（node 3 / 5 / 10），其余四队打普通组（node 2）
```
用 lv60 叠 3 的 20 人、lv90 叠 8 的 20 人各跑一遍 1~100 层，卡点分别在 61 层与 71 层（每层统计 5 场胜场数）；带装备会比这个数字高，100 层留给终盘。第 100 层刻意留在「满配 + 好装备」才够得着的位置——它是赛季目标，不是随手能刷的关卡。

### 18.4 周期：每两周（14 天）一期
```js
EPOCH = Date.UTC(2026, 0, 5)                     // 第 1 期起点（周一）
idx   = floor((utcMidnight(now) - EPOCH) / 86400000 / 14)
id    = `R${idx + 1}`
```
- `riftState(state, now)` 惰性迁移：`cycle` 变了就把 `floor` 归零、次数填满；`day` 变了只补次数。**`best` 不随换期清零**，界面显示"历史最高"。
- 敌人的种子是 `rift${cycle}:${floor}:${slot}`，换期即换组合；奖励按层数发，层数重置就能再领一遍——这正是「奖励每两周刷新」的实现方式（不做第二套奖励表）。
- 每日 3 次、一次最多连爬 10 层（`RIFT_RUN_MAX`）：5 队 × 10 层 = 50 场模拟，一次点完约 20ms，再多会让手机端点击出现可感知的停顿。

### 18.5 五套编队
`squad.js` 的 `SQUAD_KEYS` 从 `a/b/c` 扩到 `a~e`（一队~五队）。`riftParty(state, data)` 按顺序取 `squadMembers`，**空的那套用当前队伍顶上**并标 `filled: false`——新玩家只有一队时也能玩，界面上会写"空位用当前队伍顶上"，不会偷偷拿空阵去送。
融灾禁区不进 `SQUAD_MODES`：它不需要"选哪一套"，因为五套全上。队伍页的编队面板为它单独渲染一行（五组头像 + 五个 chip，点 chip 直接打开对应队的编辑器），`squadEditor` 收到 `mode='rift'` 时只存人、不改 `squadPick`。

### 18.6 校猫头像（几经反复，现在是对的）
最初 `Portrait_Small_Monster_catboss.webp` 用的是 `story-小煤球`（白色毛团），后来又变成「无上荣宠」那张表情包，都不是校猫；M15 还试过从造物图标里拿戴金项圈的黑猫雕像（`Icon_Creation_055`），那是一尊埃及猫摆件，也不是校猫本人。

## 19. M16：改名「挂机前夜」、挂机层默认取「有收益的最高层」

### 19.1 改名

### 19.2 问题：挂机层跟着攻坚层跑，胜率 0 就零收益
`收益 = 胜率 × 单场收益`，胜率 0 的关收益就是 0。但 `state.stage` 一直是"正在打的那一关"：攻坚时 `stage = maxStage + 1`，挂机也跟着过去；一旦这一关——或 `maxStage` 本身——打不过（侥幸首通、换过队伍、叠位被清、造物被卸），在线挂机空转，**离线结算也一直是 0**。原来的兜底只在"前线失败"时退回 `maxStage`，而 `maxStage` 自己也可能打不过。

### 19.3 判定：从想打的关往下扫，第一个打得过的层才是该挂的层
```js
farmTargetStage(state)          // 想挂的那一关 = min(stage, maxStage)（攻坚层不能按它结算）
farmableStage(state, data, from) // 从 from 往下扫，每关最多试 FARM_PROBES=2 场，最多扫 FARM_SCAN_MAX=60 关
                                 // → { stage, from, fellBack, hopeless? }
```
- 扫描结果用 `battleSig(state)` 缓存（最高通关 / 队伍 / roster 等级·叠位·突破 / 造物 / 命轮密契 / 钥令 / 策略），升级、换装备、换队伍后签名变化即自动失效；缓存上限 12 条，单场模拟约 1ms，不会卡。
- 扫满 60 关都没赢过 → `hopeless: true`，按 `max(1, from - 60)` 结算，不硬撑。
- `offlineReport` 用 `farmableStage` 的层结算，多返回 `wantStage` / `fellBack` / `hopeless`；6 次探针全擦边但扫描时赢过（胜率本来就低）时按 `1/6` 兜底，避免又变成零收益。
- `claimOffline` 领完收益后把 `state.stage` 也切到结算层——否则领完又回去打零收益的关，下次离线还是 0。`main.js` 两处 `claimOffline(app.state, null)` 改成传 `rep`，就是为了这个（收益为 0 但仍需切层的那一支）。
- `applyResult` 失败分支改成问 `farmableStage`：前线失手立刻退；在**已通关**的关上连输 `FARM_STUCK_LOSSES = 3` 场也退（返回 `rw.retreatTo` / `fellBack` / `stuck`）。手动挂机不参与自动退层——关卡是玩家自己选的，只提示不强制。

### 19.4 界面
- 战斗页当前关胜率 0 时，收益面板下面标黄一行：`⚠ 第 X 关胜率 0，挂在这儿没有收益；有收益的最高层是第 Y 关。` 带一颗<b>一键退回</b>按钮（`data-bv="fallback"`），点完直接切层并重开战斗流。

## 20. M17：联名彩蛋角色（9 位社区主播）与「星辉直播间」

### 20.1 为什么做成彩蛋而不是普通角色
9 位主播在《忘却前夜》原作里不存在，不能进召唤池，也不该影响抽卡期望与「史诗收藏家」这类成就。做法：

- 角色定义放在 `src/core/creators.js`（不走 `game-data.json`，避免污染官方数据），`indexData` 里并进 `awakeners`，`avail` 统一 `'GIFT'`；
- `pullOnce` 的池子加一条 `!a.creator`，300 抽实测一个都抽不到（测试里也是这么断言的）；
- 稀有度全部 SR：白送的角色如果按 SSR 发，会顺手把「拥有 N 名史诗」的成就喂过去；
- 属性取 SR 中位（base CON/ATK/DEF ≈ 34/32/32、scale ≈ 1.6/1.5/1.5），按类型微调（守护偏 CON/DEF、突击偏 ATK），比初始四人强一点，明显弱于主力 SSR。

### 20.2 技能：按昵称意象手写
官方角色的 kit 是「类型模板 + 原作文本数值反推」（`skills.js`），彩蛋角色没有原作文本，所以在 `CREATOR_KITS` 里直接给 7 槽：

| 角色 | 界域 / 类型 | 设计来源 | 招牌 |
| --- | --- | --- | --- |
| 萨摩不耶 | 混沌 / 守护 | 雪橇犬：雪原、拆家、摇尾巴；社区昵称「一哥」「饺子」 | 雪原守望（全队盾 + 全体降攻）、拆家 |
| 梦依流苏 | 深海 / 合唱 | 流苏与丝线：织、缠、缝 | 织梦（群疗 + 群盾）、千丝缠（降攻 + 虚弱） |

| 鼠王 | 血肉 / 突击 | 鼠群与瘟疫 | 鼠群奔涌（4 段 + 中毒）、瘟疫之牙、鼠王加冕 |
| 魔龙_D | 混沌 / 突击 | 龙息、龙鳞、咆哮 | 龙息（群体灼烧）、龙鳞（护盾 + 反击）、灭世咆哮 |

成长用与 `skills.js` 相同的 `GROWTH(level) = 0.98 + 0.03 × level`，所以技能等级 Lv.1–5 的成长曲线和官方角色一致。四界域 × 三类型都有人，组 4 人队能吃到同域加成。

**专属特性（`trait`）**：角色数据上多一个可选字段，目前只有萨摩不耶有——社区管她叫「一哥」「饺子」，见了弥萨格那只校猫（奖励首领 `catboss`）就护食：

```js
trait: { zh: '一哥护饺子', desc: '对上奖励首领「校猫」时，造成的伤害 +50%。', vs: { catboss: 0.5 } }
```

`vs` 是「目标 id → 增伤比例」的映射：`allyDef` 把 `a.trait` 透传给单位，`makeUnit` 再带进模拟，`battle.js` 的 `damage()` 里按 `tgt.mid` 查表乘算（`raw *= 1 + vs[tgt.mid]`）。所以它只在打校猫时生效——其他敌人、竞技场对手（防守单位没有 `mid`）都不受影响，也不用改任何技能文本。以后要加「对某类敌人特攻」，照这个字段填就行。

### 20.3 获取：签到 + 常驻活动
- **签到**：`SIGNIN_GIFTS = [3 天 → 萨摩不耶, 7 天 → 梦依流苏, 15 天 → 夏茉琳]`，判据是 `state.stats.signins`（跨月累计，不清零）。`syncSigninGifts` 幂等，`boot()` 与每次签到后都调一次，所以老玩家进游戏会一次性补发已达标的那几位。
- **活动「星辉直播间」**（`src/core/event.js`）：常驻不限期——单机同人站，玩家可能隔一个月才回来，限时活动只会让人空手而归。
  - 每日任务：在线挂机 20 场 +30、赢 15 场 +30、首次通关 2 关 +40；UTC 日重置。
  - **离线场次不计入**：8 小时离线约 1150 场，睡一觉就把任务做完了，任务也就没意义了。离线收益本身照发，只是不算「今天陪播」。
  - 推图里程碑：最高通关每 10 关 +10 人气（上限 100 关），一次性领取。
  - 签到每次 +5 人气（`fameOf` 里按 `stats.signins` 派生，不额外记账）。
  - 档位 60 / 140 / 240 / 360 / 520 / 700，对应 立誓0氪 / 鼠王 / 朝星 / 爱丽丝 / 魔龙_D / 路过的耄耋；第一天做满任务约 100 人气，一周左右集齐。
- `state.event = { day, daily: { battles, wins, clears, claimed }, fame, tiers, miles }`，`migrate` 里补默认值，`eventState` 惰性按日重置。
